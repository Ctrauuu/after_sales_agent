# 09c · 后端进阶——权限、记忆、RAG

> 基础查询跑通后，这一步给系统加上"灵魂"：谁查什么数据由权限说了算、Agent 能记住上次的分析结论、能检索售后政策法规。

---

## 目标

*   实现 MCP 层 RBAC 权限注入
    
*   配置长期记忆引擎（FTS5 + Milvus）
    
*   构建售后知识库 RAG（Milvus 向量库 + 文档入库）
    

## 步骤

### 1. 权限注入

当前项目使用 Hermes 插件签名身份，再由六个 MCP 共用唯一授权入口。不要把
`user_context` 暴露成模型可填写的工具参数：

```python
from fastmcp import Context
from mcp_suning.security.rbac import (
    authorize_mcp_request,
    build_scope_clause,
    interceptor,
)

@mcp.tool()
def search_orders(ctx: Context, **filters):
    _, safe_filters = authorize_mcp_request(
        ctx, "search_orders", filters
    )
    scope_sql, scope_params = build_scope_clause(
        safe_filters,
        region_column="o.region_code",
        city_column="o.city_code",
        category_column="o.category_code",
    )
    rows = execute_readonly_query(scope_sql, scope_params)
    return interceptor.mask_sensitive_data(
        rows, safe_filters["data_scope"]
    )
```

`authorize_mcp_request()` 必须位于首次数据库读取之前；后续 SQL 只能使用
`safe_filters` 生成的 `allowed_*`，返回前必须按其中的 `data_scope` 脱敏。

运行依赖：

- Hermes 与 MCP 两端配置相同的 `SUNING_MCP_BRIDGE_SECRET`
- 两端配置相同的 `SUNING_IDENTITY_ISSUER`
- Redis 用于 `jti` 防重放
- Hermes 只启用 `suning-rbac-bridge` 工具，六个私有 MCP 不直接暴露给模型

验证：运行 `cd backend && .venv/bin/pytest -q`，再用不同角色执行真实 MCP
验收，确认允许、拒绝、行级过滤、群聊脱敏和重放拒绝都生效。

### 2. 配置长期记忆

Hermes 内置 FTS5 记忆引擎，确认已启用：

```bash
# 查看记忆配置
hermes config get memory

# 启用记忆功能（默认应已启用）
hermes config set memory.enabled true
hermes config set memory.fts5_index_path ~/.hermes/memory.db
```

配置 Milvus 用于记忆的语义检索通道：

```bash
# 启动 Milvus
docker run -d --name milvus-standalone \
  -p 19530:19530 -p 9091:9091 \
  milvusdb/milvus:latest milvus run standalone

# 在 Hermes 中配置 Milvus 连接
hermes config set milvus.host localhost
hermes config set milvus.port 19530
```

验证记忆功能：

```bash

# 第3轮: "上次分析的空调退单原因是什么？"（应能召回之前的结论）
```

#### 3b. 文档入库脚本

```python
# scripts/ingest_knowledge.py

from pymilvus import Collection, connections
from dashscope import TextEmbedding
import os
import re

# 连接 Milvus
connections.connect(host="localhost", port="19530")

# 创建 Collection（如果不存在）
collection = Collection("knowledge_chunks")

def chunk_text(text: str, chunk_size: int = 500) -> list[dict]:
    """将长文本按段落切分，每段带元数据"""
    paragraphs = text.split("\n\n")

    chunks = [ ]

    for i, para in enumerate(paragraphs):
        if para.strip():
            # 简单提取标题
            title = para.split("\n")[0].strip("# ")[:100]
            chunks.append({
                "content": para[:chunk_size],
                "title": title,
            })
    return chunks

def ingest_directory(input_dir: str):
    """遍历目录下所有 .txt 文件入库"""
    for filename in os.listdir(input_dir):
        if not filename.endswith(".txt"):
            continue

        with open(os.path.join(input_dir, filename), "r", encoding="utf-8") as f:
            text = f.read()

        chunks = chunk_text(text)
        for i, chunk in enumerate(chunks):
            # 调用百炼 Embedding
            resp = TextEmbedding.call(
                model="text-embedding-v3",
                input=chunk["content"],
            )
            vector = resp["output"]["embeddings"][0]["embedding"]

            # 入库
            collection.insert([{
                "id": f"{filename}_{i}",
                "vector": vector,
                "content": chunk["content"],
                "source": filename,
                "title": chunk["title"],
            }])

    collection.flush()
    print(f"已入库 {input_dir} 下所有文档")

if __name__ == "__main__":
    ingest_directory("mock-files/")
```

#### 3c. 配置 Hermes 使用 RAG

```bash
# 创建自定义 Skill，让 Agent 在回答政策类问题时检索知识库
mkdir -p ~/.hermes/skills
```

创建 Skill 文件：`~/.hermes/skills/aftersale-knowledge.yaml`

```yaml
name: aftersale-knowledge
description: 检索售后政策/法规/条款回答用户问题
trigger_patterns:
  - "保修"
  - "三包"
  - "退货政策"
  - "售后条款"
workflow:
  - step: 1
    action: search_milvus
    collection: knowledge_chunks
    query: "{{user_question}}"
    top_k: 3
  - step: 2
    action: llm_generate
    prompt: "基于以下条款片段回答用户问题，必须引用来源"
    context: "{{step_1_results}}"
```
