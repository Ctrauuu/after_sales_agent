# 09b · 后端核心——MCP Server 开发

> 这一步是建数据管道。用 FastMCP 把苏宁的订单、售后工单、商品、物流数据封装成 MCP 工具，让 Agent 能通过对话查到真实的业务数据（先用模拟数据跑通）。

---

## 目标

*   创建 5 个 MCP Server（订单/售后/商品/物流/支付）
    
*   每个 Server 提供对应的查询工具
    
*   验证 Agent 能通过 MCP 调用获取模拟数据
    

## 步骤

### 1. 安装 FastMCP

```bash
pip install fastmcp pymysql sqlalchemy
```

### 2. 创建订单 MCP Server

```python
# backend/mcp_suning/servers/order.py

from fastmcp import FastMCP
import sqlalchemy as sa

mcp = FastMCP("suning-order")

# 数据库连接（开发环境：本地 MySQL 实例，加载模拟数据）
# 上线前切为苏宁只读副本地址
engine = sa.create_engine("mysql+pymysql://root:password@localhost:3306/suning_aftersale")

@mcp.tool()
async def search_orders(
    status: str = None,
    category: str = None,
    date_range_days: int = 7,
    region: str = None,
    limit: int = 50,
) -> list[dict]:
    """
    搜索订单列表。
    参数:
    - status: 订单状态 (returned/completed/...)
    - category: 品类筛选
    - date_range_days: 查询近N天的数据
    - region: 区域编码 (HD=华东)
    - limit: 最大返回数
    """
    with engine.connect() as conn:
        query = """
            SELECT o.order_id, o.user_id, o.channel, o.region_code,
                   o.city_code, o.order_amount, o.create_time, o.order_status,
                   r.return_id, r.return_reason_desc, r.return_status
            FROM t_order_main o
            LEFT JOIN t_aftersale_return r ON o.order_id = r.order_id
            WHERE o.create_time > UNIX_TIMESTAMP(DATE_SUB(NOW(), INTERVAL :days DAY))
        """
        params = {"days": date_range_days, "limit": limit}

        if category:
            query += " AND r.sku_code IN (SELECT sku_code FROM t_product_sku WHERE category_l3_code LIKE :cat)"
            params["cat"] = f"%{category}%"

        if region:
            query += " AND o.region_code = :region"
            params["region"] = region

        query += " LIMIT :limit"

        result = conn.execute(sa.text(query), params)
        return [dict(row._mapping) for row in result]

@mcp.tool()
async def get_order_detail(order_id: int) -> dict:
    """获取单个订单的详细信息"""
    with engine.connect() as conn:
        result = conn.execute(
            sa.text("SELECT * FROM t_order_main WHERE order_id = :oid"),
            {"oid": order_id}
        )
        row = result.fetchone()
        return dict(row._mapping) if row else {"error": "订单不存在"}

if __name__ == "__main__":
    mcp.run(host="0.0.0.0", port=8101)
```

### 3. 创建售后工单 MCP Server

售后服务同时包含动态分析和固定业务 API：

- `query_return_stats_nl2sql`、`query_aftersale_nl2sql` 使用 `nl2sql.runtime` 中的共用 Pipeline。
- `query_sku_return_rate` 使用订单-SKU 明细和固定参数化 SQL 计算退单订单率，不交给 NL2SQL。
- `get_aftersale_workflow` 的输入和查询结构明确，继续使用固定参数化 SQL。

```python
# backend/mcp_suning/servers/aftersale.py

from fastmcp import Context, FastMCP

from mcp_suning.security.rbac import authorize_mcp_request, interceptor
from nl2sql.runtime import nl2sql_pipeline


mcp = FastMCP("mcp-aftersale")


@mcp.tool(name="query_return_stats_nl2sql")
def query_return_stats_nl2sql(
    ctx: Context,
    group_by: str = "category",
    date_range_days: int = 7,
    category: str = "",
) -> list[dict]:
    """输入：MCP 上下文、分组维度、时间范围和可选品类。

    输出：按权限脱敏的退单聚合统计列表。
    功能：把结构化统计参数转成受控问题，并交给共用 NL2SQL Pipeline。
    """
    _, safe_filters = authorize_mcp_request(
        ctx,
        "query_return_stats_nl2sql",
        {"date_range_days": date_range_days, "category": category},
    )
    dimensions = {
        "day": "按退单申请日期分组",
        "category": "按品类编码和名称分组",
        "reason": "按退单原因编码和说明分组",
        "region": "按区域编码分组",
        "brand": "按品牌编码和名称分组",
    }
    if group_by not in dimensions:
        raise ValueError("不支持的退单统计维度")
    question = (
        f"统计最近 {safe_filters['date_range_days']} 天的退单数据，"
        f"{dimensions[group_by]}，返回退单量和退单金额并按退单量降序。"
    )
    result = nl2sql_pipeline.run(question, safe_filters)
    return interceptor.mask_sensitive_data(
        result["rows"], safe_filters["data_scope"]
    )


@mcp.tool(name="query_aftersale_nl2sql")
def query_aftersale_nl2sql(question: str, ctx: Context) -> dict:
    """输入：自然语言售后分析问题和 MCP 上下文。

    输出：最终 SQL、行数和按权限脱敏的聚合结果。
    功能：使用共用 Pipeline 承接复杂运营分析和临时统计。
    """
    normalized_question = question.strip()
    if not normalized_question:
        raise ValueError("question 不能为空")
    _, safe_filters = authorize_mcp_request(
        ctx, "query_aftersale_nl2sql", {}
    )
    result = nl2sql_pipeline.run(normalized_question, safe_filters)
    response = {
        "success": True,
        "question": normalized_question,
        "sql": result["sql"],
        "row_count": len(result["rows"]),
        "rows": result["rows"],
    }
    return interceptor.mask_sensitive_data(
        response, safe_filters["data_scope"]
    )


# get_aftersale_workflow 继续使用固定参数化 SQL，完整实现见项目源码。
```

完整维度约束、字段别名和响应代码以 `backend/mcp_suning/servers/aftersale.py` 为准。

### 5. 注册 MCP Server 到 Hermes

```bash
# 启动 MCP Server（每个在一个终端窗口）
python -m mcp_suning.servers.order &
python -m mcp_suning.servers.aftersale &

# 在 Hermes 中注册 MCP 连接
hermes mcp add suning-order http://localhost:8101/mcp
hermes mcp add suning-aftersale http://localhost:8102/mcp

# 查看已注册的 MCP 连接
hermes mcp list
```

## 避坑建议

*   开发环境安装本地 MySQL 实例，加载模拟数据；上线切为苏宁只读副本连接串。全程不用 SQLite，避免 MySQL/SQLite 方言差异导致上线后 SQL 报错
    
*   MCP Server 返回数据量大的话，在 Tool 内部主动加 LIMIT 限制
    
*   MCP 调用超时可调整 `hermes config set mcp_timeout 30`
