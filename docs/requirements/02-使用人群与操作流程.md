# 02 · 使用人群与操作流程

> 这篇文档讲的是"谁在用、怎么用"。每个人打开这个系统看到的东西不一样——同样问"退单量多少"，全国运营总监看到的数字跟华东大区经理看到的不一样，权限控制了数据范围。

---

## 一、使用人群

所有用户均为苏宁内部员工，通过飞书/企微/钉钉的企业账号认证后使用。按角色分为五类：

| 角色 | 典型岗位 | 核心诉求 | 数据权限范围 | 可查订单范围 |
| --- | --- | --- | --- | --- |
| 售后运营 | 售后运营经理/专员 | 退单趋势、品类分布、SLA时效 | 全品类、全区域 | 全部 |
| 客服管理 | 客服主管/组长 | 单订单全链路、投诉追溯 | 本团队服务范围 | 本团队关联订单 |
| 品控/供应链 | 质量工程师、采购经理 | 退单原因分析、高退货SKU识别 | 对应品类 | 对应品类订单 |
| 区域管理 | 大区经理/城市经理 | 本区售后指标、仓储物流时效 | 本区域数据 | 本区域订单 |
| 高层决策 | 总监/VP/总经理 | 成本趋势、满意度、大盘概览 | 全量脱敏汇总 | 汇总级（不可查单） |

## 二、操作流程

### 2.1 首次接入流程

```mermaid
flowchart TD
    A[管理员在管理后台添加用户] --> B[关联用户的企业IM账号<br/>飞书open_id / 企微user_id / 钉钉user_id]
    B --> C[分配角色和权限范围<br/>例: 华东大区经理 → 区域角色 → 华东三省一市]
    C --> D[用户在IM中搜索机器人<br/>飞书/企微/钉钉内搜索并添加]
    D --> E[首次私聊: Agent 发送欢迎语<br/>告知可用功能和使用方式]
    E --> F[用户开始使用]
```

### 2.2 日常使用主流程

```mermaid
flowchart TD
    A[用户在IM中 @机器人 提问<br/>或在机器人私聊中提问] --> B[Hermes Gateway 接收消息]
    B --> C{Hermes 请求级身份是否完整?<br/>平台 + 发送者ID + 会话类型}
    C -->|未识别| D[返回: 未授权, 请联系管理员]
    C -->|已识别| E{是否为支持的消息类型?<br/>文本 / 语音}
    E -->|不支持| F[返回: 暂不支持该消息类型]
    E -->|支持| G[Agent 解析用户意图]
    G --> H{是多轮追问?}
    H -->|是| I[加载历史会话上下文<br/>补全实体和时间范围]
    H -->|否| J[开启新会话]
    I --> K[Agent 仅生成业务查询参数<br/>不携带工号/角色/权限]
    J --> K
    K --> N[调用 suning-rbac-bridge<br/>签发工具绑定的短期身份凭证]
    N --> L{MCP 验签并查询现有绑定表<br/>计算 RBAC 范围}
    L -->|无权限| M[返回: 权限不足,<br/>你只能查询xxx范围的数据]
    L -->|有权限| O[MCP Server: 订单数据]
    L -->|有权限| P[MCP Server: 售后工单]
    L -->|有权限| Q[MCP Server: 商品/品类]
    L -->|有权限| R[MCP Server: 物流/仓储]
    O --> S[Agent 聚合多源数据]
    P --> S
    Q --> S
    R --> S
    S --> T[生成结构化回复<br/>文字 + 数据表格 + 图表]
    T --> U[写入长期记忆<br/>存储本问分析结论]
    U --> V[回复到IM]
```

## 三、权限控制流程

```mermaid
flowchart TD
    A[Hermes 调用桥接插件] --> B[读取请求级平台发送者身份<br/>签发30秒 HMAC 凭证]
    B --> C[MCP 验签 + Redis jti 防重放<br/>按 platform + platform_user_id 查现有绑定]
    C --> C1{加载内部用户、角色和附加权限<br/>角色上限与用户范围求交}
    C1 --> D[售后退单运营<br/>→ 全品类/全区域<br/>→ 可查明细]
    C1 --> E[区域经理<br/>→ 限定区域='华东'<br/>→ 可查本区脱敏明细]
    C1 --> F[高层决策<br/>→ 全量汇总<br/>→ 不可查明细单号]
    D --> G{查询粒度检查}
    E --> G
    F --> G
    G -->|已脱敏通过| H[首次 SQL 前追加参数化权限条件<br/>结果按 data_scope 脱敏]
    G -->|越权/明细级| I[阻断并提示权限不足]
```

## 四、群聊 vs 私聊行为差异

| 场景 | 群聊 @机器人 | 私聊机器人 |
| --- | --- | --- |
| 权限判定 | 以 @者 的身份计算 | 以聊天对象身份计算 |
| 回复可见性 | 全群可见 | 仅自己可见 |
| 敏感数据 | 自动脱敏（如隐藏用户手机号中间四位） | 按角色展示完整程度 |
| 会话上下文 | 群会话独立，不同群不串 | 个人会话独立 |
| 图表展示 | 降级为文字摘要（部分IM群聊不支持图表） | 展示完整图表 |
